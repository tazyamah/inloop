# レビュー依頼のプロトコル（草案）

この文書は設計中の草案です。実装時にADRで確定させます。

## 依頼票

| 項目 | 作り手 | 内容 |
|---|---|---|
| 観点 | AI | 「このエラー時に既存データを残す方針でよいか」のような具体的な問い |
| 種別 | エンジン | `required`（信頼境界ルールによる必須）または`optional`（AIによる任意） |
| 対象 | エンジン | 関係するシンボルを理解順に並べたもの、データの流れ、影響範囲 |
| 証拠 | エンジン＋CI | 対応するテストと結果、静的解析などの結果 |
| 回答 | 人 | 下記の列挙値と、行・シンボルに紐づくコメント |

AIが渡す入力は、観点の文、対象シンボルIDの列、commit範囲だけです。コードは渡しません。

## AIとのやり取り

依頼時、AIに返すのは依頼IDと状態だけです。

```text
request_review(viewpoint, symbols, range) -> { id: "R12", status: "pending" }
```

回答は、UIの「まとめて送信」で1通にまとめ、1行に1つの回答を書く形式で返します。

```text
R12 ok
R13 fix src/auth.ts#login#L42 "トークン期限切れは401で返す"
R13 ask src/auth.ts#login#L50-L53 "リトライは冪等?"
R14 ask "全体として妥当?"
R15 hold
```

| 値 | 意味 | 1つの依頼に付けられる数 |
|---|---|---|
| `ok` | 承認 | 単独の1行のみ |
| `hold` | 保留 | 単独の1行のみ |
| `fix` | 修正依頼（コメント必須） | 行ごとに複数 |
| `ask` | 質問（コメント必須） | 行ごとに複数 |

参照は、シンボルID（依頼全体へのコメントでは省略）、行（`#L42`）、行範囲（`#L50-L53`）のいずれかです。参照は依頼票に含まれるシンボルと、その表示範囲内の行に限ります。1行でも不正があれば、その回答全体を記録しません。

依頼の状態は、`fix`が1つでもあれば`fixing`、なければ`ask`があれば`answering`、`hold`なら`held`、`ok`なら`approved`になります。

コード抜粋は返しません。AIはrepositoryを読めるため、場所を示せば十分です。

## UIでの回答の操作

GitHubのコードレビューと同じく、行を起点に回答します。

- コード行をクリックすると、その行の直下にコメント欄が開く。Shift+クリックで行範囲にする
- その行のシンボルを含む未回答の依頼が複数あれば、先に宛先の依頼を選ぶ（表示中の依頼が先頭）
- 追加したコメントは行の下に吹き出しとして残り、編集・削除できる
- コメントのない依頼は「承認」か「保留」を選ぶ。行に紐づかない質問は「依頼全体にコメント」から書く
- 書きかけのコメントがある間は送信できない

## 状態遷移

```text
pending ─ ok ──────────────► approved
   │
   ├─ fix（1つ以上） ─► fixing ─ 再依頼（差分のみ） ─► pending
   ├─ ask（1つ以上） ─► answering ─► pending
   └─ hold ─► held ─► pending
```

承認後に対象シンボルの本文が変わった場合、その依頼は`pending`に戻ります。
