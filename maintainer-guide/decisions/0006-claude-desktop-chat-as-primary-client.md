# ADR-0006: 当面の主なクライアントをClaude Desktopの通常の会話にする

- 状態: Superseded（ADR-0037）
- 日付: 2026-10-10
- Supersedes: なし

## 背景

ADR-0003の構成は、ホストがMCP AppsのUIを表示し、UIからの`sendMessage`を会話に入れ、同じ画面でAIがローカルのファイルを扱えることを前提にしている。どのクライアントがこれを満たすかは未検証だった。

## 決定

- 当面の開発と検証は、Claude Desktopの通常の会話を主なクライアントとして行う。
- 他のクライアント（Claude Code、Codex、VS Code）は、引き続き確認対象とし、結果に応じて新しいADRで見直す。
- MCP Appsを表示できないクライアント向けの代替経路（ブラウザで開くUIと`get_review_result`）は維持する。

## 理由

2026-10-10の確認で、Claude Desktopの通常の会話は次をすべて満たした。

- MCPサーバーへの接続と、`visibility: ["app"]`のツールをAIから隠すこと
- レビューUIの表示（ホストのテーマ反映、全画面表示ボタン）
- UIからの回答が1通のメッセージとして会話に入り、AIがそれを読み取って作業を再開すること（行範囲の参照と複数依頼の同時回答を含む）
- 同じ会話で、AIがローカルのrepositoryのファイルを読み、編集すること

一方、Claudeアプリのクラウドセッションからデバイス連携でサーバーを中継した場合は、ツールは使えたがUIは表示されなかった。

## 影響

- UIの動作確認は、テスト用ホストでの自動テストに加え、Claude Desktopでの手動確認を基準にする。
- Claude Desktopのホストとしての挙動（ツールの戻り値のうちAIに渡る部分、`sendMessage`の扱いなど）に合わせた判断が増える。他のクライアントに広げるときに差異が出うる。

## 却下した代替案

- 他のクライアントの確認を待ってから決める: 往復の全項目を満たすクライアントがすでにあり、開発を止める理由が小さい。
- Claudeアプリのクラウドセッション（デバイス連携）を主にする: UIが表示されない。

## 検証

- [クライアント検証の結果](../client-verification-results.md)の表。
- 主要な変更のたびに、Claude Desktopで依頼→回答→AIの再開を確認する。
