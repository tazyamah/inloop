# ADR-0003: MCPサーバー＋MCP AppsとしてAIクライアントにホストされる

- 状態: Accepted
- 日付: 2026-10-10
- Supersedes: なし

## 背景

レビューの往復をAIクライアントの中で完結させたい。また、AIクライアントのアプリ利用とAPI利用は課金体系が異なるため、API課金を避けたい。

## 決定

- inloopはMCPサーバーとして実装し、AIクライアントから起動される。
- レビューUIはMCP Appsとして、クライアントの画面内に表示する。UIからの回答は、サーバーのツール呼び出しと会話へのメッセージ送信によってAIの作業を再開させる。
- MCPサーバーはLLMを呼び出さない。
- 自作のIDE（エディタ、チャット画面、エージェント）は作らない。
- MCP Appsに対応しないクライアント向けに、同じUIをローカルのブラウザで開く代替経路を用意する。
- ClaudeのWeb版（リモートMCPサーバーが必要）は対象にしない。

## 理由

- モデルの推論をクライアント側に任せることで、アプリのプランの範囲で使え、API課金が発生しない。
- MCPに乗れば、複数のクライアントに共通の仕組みで対応できる。
- 人は編集をせずレビューだけを担当する設計なので、エディタは不要である。

## 影響

- UIや会話へのメッセージもプランの利用上限に計上されるため、ADR-0004の節約が必要になる。
- クライアントごとのMCP Apps対応状況に依存する。

## 却下した代替案

- 自作IDEからAIを呼ぶ方式: APIまたはCLIの包み込みが必要で、作る量も多い。
- 特定クライアント専用の仕組み（Claudeのartifactなど）だけに依存する方式: クライアント間で共通にできない。

## 検証

- 実際のクライアントで、ローカルrepositoryの編集とMCP AppsのUI表示が同じ画面で両立することを確認する（未検証、handoff参照）。
- MCPサーバーの依存関係にLLMのSDKが含まれないことを確認する。
