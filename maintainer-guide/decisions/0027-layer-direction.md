# ADR-0027: レイヤー間の依存の向きを検査し、違反を必須の依頼にする

- 状態: Accepted
- 日付: 2026-10-12
- Supersedes: なし（ADR-0023の「向きの検査は、この判断では足さない」を足す。ADR-0023の結論は変えない）

## 背景

ADR-0023は`layers`で依頼票の`layer`を決めたが、レイヤー間の依存の向きの検査は、実際の依頼で`layer`を使ってから決めるとして持ち越した。依存の向き（画面からデータベースを直接使わない、など）は、設計の約束がコードで破られていないかを人が確かめるべき点で、信頼境界ルールと同じく、AIの判断で省けない形にしたい（AGENTS.md）。

## 決定

- `layers`の項目に、省略できる`mayUse`（レイヤーのidの列）を足す。`format`は1のまま。
  - `mayUse`がなければ、そのレイヤーのコードは何を使ってもよい（制限なし）。空の列`[]`なら、同じレイヤー以外を使えない。同じレイヤーは常に使える。
  - `mayUse`に、`layers`にないidを書くと、読み込みで拒否する。
  - どちらか一方がレイヤーのないファイルなら、検査しない。
- 検査の単位と材料は、信頼境界ルールと同じ。範囲で変わった宣言（と変わった最上位の文）が直接使うリポジトリの宣言（ADR-0015の`references`の`internal`）のファイルを、レイヤーに当てる。使う側のレイヤーの`mayUse`にない別のレイヤーを使っていれば違反。
- 違反した単位には、組み込みのルール`layer-direction`が当たり、信頼境界ルールと同じように、単位ごとの必須の依頼になる（ADR-0022）。問いは、決まった文に`レイヤーの向きに反する使い方: 使う側→使われる側`を足したもの。`inloop check`も同じ判定を使う。
- `layer-direction`は`inloop.json`のルールでは使えない（`inloop-config`と同じ）。
- 判定は、範囲の基点と作業ツリーの`layers`の両方で行い、どちらかに反すれば当てる。AIが`mayUse`を緩めて違反を通しても、その範囲では緩める前の約束で当たる（ADR-0022のルールの和と同じ考え方。`inloop.json`の変更自体も`inloop-config`が当たる）。
- `inloop new`の雛形（サーバー、手元）の`inloop.json`に`layers`を足す。`test`（`server/**/*.test.ts`、制限なし）、`db`（`server/db.ts`、何も使わない）、`http`（`server/app.ts`・`server/index.ts`、`db`だけ）、`web`（`web/**`、何も使わない）。

## 理由

- 違反を必須の依頼にするのは、設計の約束を守る判断を人に残すため。違反を一律に拒否すると、約束を見直すべきときに進めなくなる。
- 判断の材料を直接の依存に限るのは、`references`が決定的に作れる範囲であり、依頼票の依存の図と一致するため（ADR-0015、ADR-0020）。間接の依存は、途中の宣言が変わらないので当てない。
- レイヤーのないファイルを検査しないのは、レイヤーを定義していないものの約束はないため。外の名前（標準ライブラリなど）は`internal`に入らず、対象外。

## 影響

- 記録の版は上げない（依頼票の形は変わらず、必須の依頼の`triggeredBy`に`layer-direction`が現れるだけ）。古い実装は、それを普通のルールのidとして読む。
- `layers`に`mayUse`を書いたリポジトリでは、`request_review`のたびに、変わった宣言のレイヤーも調べる。
- 間接の依存、別のファイルから再exportした名前、型だけの参照以外の動的な使い方は追わない。型としての参照は`internal`に入る。

## 却下した代替案

- 違反を拒否して依頼を作らない: 人に判断を残せない。
- `mayUse`を信頼境界ルールの当て方（`{layer: ...}`）にする: 向きは2つのレイヤーの組で決まり、1つのレイヤーを指す当て方に合わない。
- 作業ツリーの`layers`だけで判定する: AIが`mayUse`を緩めれば違反を通せる。

## 検証

`npm test`で、許された向きは当たらず許されない向きが`layer-direction`として当たること、`mayUse`がないレイヤーとレイヤーのないファイルは検査しないこと、基点の`mayUse`を緩めても当たること、最上位の文の違反が当たること、定義にないレイヤーを拒否することを確かめる。実際のクライアントで、AIが違反の必須の依頼を人に伝えるかは未検証。
