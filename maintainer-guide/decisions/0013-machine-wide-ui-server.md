# ADR-0013: 画面をマシン全体で1つのサーバーから、アプリ名のURLで配る

- 状態: Accepted
- 日付: 2026-10-11
- Supersedes: ADR-0012の一部（ポート、鍵、URLの形）。ブラウザのホストがMCP Appsのホストの役を務めること、`wait`で回答を待つことは変えない

## 背景

ADR-0012のブラウザの経路では、MCPサーバーのプロセスごとに、空いているポートと起動ごとの鍵でURLを作っていた。そのため、サーバーが起動し直すと、それまでの画面のURLがすべて使えなくなった（2026-10-11、Claudeデスクトップアプリの中のClaude Codeで、セッションを開き直したときに起きた）。記録はリポジトリに残り続けるのに、そこへ辿るURLが残らない。利用者は、遠い未来に記録を参照したときに矛盾がないことを優先したい。

また、ADR-0010で1つのサーバーが複数のリポジトリを扱うことにしたので、URLにはどのリポジトリの依頼かを含める必要がある。ADR-0011で、`inloop`コマンドをマシンに1回入れ、アプリのリポジトリを`inloop new`・`init`で作ることにした。

確かめたこと（2026-10-11、macOS）: `appa.inloop.localhost`は、hostsの設定なしに自分のMacへ向いた（`curl`、Claudeアプリのブラウザペイン、Safariで、試験用のサーバーに届いた）。ブラウザペインから送った`fetch`の要求には、`Origin: http://appa.inloop.localhost:<ポート>`が付いた。

## 決定

### マシン全体の画面のサーバー

- `inloop`コマンドは、マシン全体で1つの画面のサーバーを、決まったポートで動かす。既定のポートは4656とし、設定で変えられる。待ち受けるのは`127.0.0.1`と`::1`だけとする。
- `inloop mcp`は起動時に、画面のサーバーが動いていなければ起動する。すでに動いていれば、それを使う。どのMCPサーバーのプロセスが起動し直しても、画面のサーバーとURLは変わらない。
- 画面のサーバーは、依頼と回答をリポジトリの記録（`<リポジトリ>/.inloop/reviews.jsonl`、ADR-0010）から読み書きする。状態を自分では持たない。同じ記録を複数のプロセスが使ってよい（ADR-0007）。

### アプリの登録とURL

- `inloop new`と`inloop init`は、アプリの名前とリポジトリの絶対パスを、利用者ごとの登録簿（`~/.inloop/apps.json`）に書く。名前は、既定でリポジトリのディレクトリ名を小文字にしたものとし、英小文字・数字・`-`に限る。すでに別のリポジトリが使っている名前は拒否し、`--name`で別の名前を指定させる。リポジトリを移したときは、移した先で`inloop init`をやり直す。
- 画面のURLは`http://<アプリ名>.inloop.localhost:<ポート>/r/<依頼ID>`とする。例: `http://appa.inloop.localhost:4656/r/R3`。
- 登録簿にない名前、登録されたリポジトリの記録にない依頼IDは、拒否する。
- `request_review`が返すURLもこの形とする。

### 鍵の代わりの確認

URLの鍵（ADR-0012の`t`）は使わない。代わりに、すべての要求で次を確かめ、合わなければ拒否する。

- Hostヘッダーが`<登録されたアプリ名>.inloop.localhost:<ポート>`であること（名前を向け直す手口、DNS rebindingへの備え）。
- 書き込みを伴う要求（UI専用のツールの呼び出し）は、Originヘッダーが同じ`http://<アプリ名>.inloop.localhost:<ポート>`であること。Originのない書き込みは拒否する。
- 書き込みを伴う要求は、`application/json`だけを受け付ける。
- 別のサイトに読ませる応答の許可（CORS）は出さない。

## 理由

- URLを決まった名前とポートにすれば、記録がある限り、いつでも同じURLで同じ画面を開ける。アプリ名がURLに入るので、どのリポジトリの依頼かもURLだけで分かる。
- 画面のサーバーを1つにすると、MCPサーバーがいくつ動いても、ポートの取り合いが起きない。MCPサーバーは画面を持たなくてよくなる。
- `*.localhost`は、ブラウザとmacOSが自分のマシンに向ける名前なので、hostsや名前解決の設定が要らない。
- 鍵が主に防いでいたのは、ブラウザで開いている別のサイトからの送信である。ブラウザはOriginを偽れないので、Originの確認で同じことを防げる。別のサイトから画面の中身を読むことは、CORSの許可を出さなければブラウザが止める。
- 鍵がなくなって防げなくなるのは、同じマシンのブラウザ以外のプログラムからの送信である。それらは記録ファイルを直接書けるので、鍵があっても防げていなかった。AIによる自己承認を防ぐことは、ADR-0012と同じく範囲外とする。
- 鍵をなくすと、AIの文脈に鍵が入らず、URLも短くなる（ADR-0004）。

- 既定のポートを4656にしたのは、電話のキーで「INLO」（I=4、N=6、L=5、O=6）と読めて覚えやすいからである。sudoなしで使える1024以上、macOSがその都度割り当てる49152未満の範囲で、日本語版Wikipediaの「TCPやUDPにおけるポート番号の一覧」（2026-10-11に参照）に載っておらず、利用者のMacで使われていなかった。最初の案の4747は、その一覧に載っていた（Apprentice、非公式）。「LOOP」の5667は、Nagiosの番号として載っていた。一覧に載っていないことは、どのソフトにも使われていないことの保証にはならないので、設定で変えられるようにする。

## 影響

- `inloop`コマンドに、画面のサーバーの起動・停止・状態の確認と、登録簿の管理が要る。ログイン時に自動で起動するか（launchdなど）は、使ってみてから決める。
- MCPサーバーのプロセスが、画面のサーバーを起動する。MCPサーバーを終了しても画面のサーバーは残る。
- 1台のMacを複数の利用者で使う場合、別の利用者も127.0.0.1の画面を開ける。今は1人で使う前提とし、必要になったら別に決める。
- 決まったポートを、ほかのソフトが使っていることがありうる。そのときは設定でポートを変える。
- ADR-0012の実装（プロセスごとのポートと鍵）は、この判断の実装で置き換える。それまでは、URLはサーバーの起動ごとに変わる。
- MCP Appsの経路（Claude Desktopの通常の会話）は変わらない。

## 却下した代替案

- MCPサーバーのプロセスごとに、ポートと鍵を保存して使い続ける: 同じ記録を使うプロセスが複数あるとポートを取り合う。URLにリポジトリが入らない。
- `*.test`など別の名前: 名前解決の設定が要る。
- ポート80で番号を消す: 管理者権限の設定が要る。必要になれば足す。
- 鍵を残し、利用者ごとのファイルに保存する: Originの確認で同じ防ぎができ、鍵はAIの文脈とURLを長くする。

## 検証

`npm test`で次を確かめる。

- 登録したアプリ名のHostでだけ画面とツールが使え、別の名前・別のHostを拒否すること
- Originのない書き込み、別のOriginからの書き込み、JSON以外の書き込みを拒否すること
- 画面のサーバーがすでに動いていれば、2つ目のMCPサーバーがそれを使い、URLが同じであること
- MCPサーバーが起動し直しても、同じURLで同じ依頼の画面が開けること

実際のクライアントで、Claudeアプリのブラウザペインと、Safari・Chromeで画面を開けることを確かめる（名前解決は確認済み、画面は未検証）。
