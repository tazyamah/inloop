# ADR-0004: AIの文脈には参照・差分・短い列挙値だけを返す

- 状態: Accepted
- 日付: 2026-10-10
- Supersedes: なし

## 背景

AIクライアントのプランには利用上限がある。レビューの往復のたびに大きな情報をAIの文脈へ入れると、利用枠を早く消費する。

## 決定

- 人が見る情報と、AIが読む情報を分ける。
- `request_review`の入力は観点の文、シンボルIDの列、commit範囲とし、戻り値は依頼IDと状態だけにする。
- 依頼票の中身はUIがサーバーから直接取得し、ツールの戻り値に載せない。
- 回答は1行1件の短い形式で、まとめて1通で返す。コード抜粋は返さない。
- 再依頼は、承認時に記録したシンボル本文のハッシュと比べて、変わった部分だけにする。
- AIから見えるツールの数と説明文を最小限にする。
- バイト圧縮（gzip、base64など）は使わない。圧縮は参照・省略・重複排除で行う。
- 1回のレビューループで消費したトークン数を計測できるようにする。

## 理由

利用枠はトークン数で数えられる。AIはrepositoryを読めるので、場所を示せば必要な範囲だけを自分で読める。バイト圧縮はトークン数をむしろ増やす。

## 影響

- AIが詳細を必要とする場合のために、`get_review_detail`のような取得手段を別に用意する。
- UIとサーバーの間の通信量は増えるが、利用枠には影響しない。

## 却下した代替案

- 依頼票の全体をツールの戻り値で返す方式: AIが読まない情報でも利用枠を消費する。

## 検証

- ツールの戻り値の大きさに上限を設け、テストで確認する。
- レビューループごとのトークン消費量を記録する。
