# ADR-0034: コードの3段目として、ファイル全体を開き、ファイル名#行の位置を受け付ける

- 状態: Accepted
- 日付: 2026-10-12
- Supersedes: なし（ADR-0017・0018の位置の形に、ファイル全体の行を足す）

## 背景

- 依頼票のコードは、シンボルの全体（畳む／開く）の2段だった。importや型の宣言など、シンボルの外の行にコメントしたいとき、位置にできなかった。サーバーは、依頼票のシンボルの表示範囲外の`ref`を拒否していた。
- 利用者の案（2026-10-12）: 畳む、変更行の前後（今の表示）、対象ファイル全体の3段にする。

## 決定

- 画面のシンボルの見出しに「ファイル全体」を足す。押すと、そのファイルの全行を、行番号つきでシンボルのコードの下に開く（押し直すと閉じる）。コードが開いているシンボルごとに出す（畳まれた依存には出さない）。開閉はシンボルごと。
- 全体の行のクリックは、位置`ファイル名#L行`（範囲は`ファイル名#L1-L5`）を会話に入れる（ADR-0032と同じ）。シンボルのない単位（設定ファイルなど）は、これまでどおり`ファイル名#L行`が位置。
- UI専用のツール`inloop_get_file`（visibility: app）が、依頼票のどれかの`file`と一致するファイルだけを、作業ツリーから返す。リポジトリの外、依頼票にないファイル、固定データ、1,000,000バイトを超えるファイルは断る。AIの文脈には返さない（ADR-0004）。
- 依頼票の作成後にファイルが変わり、シンボルのコードと作業ツリーが食い違うときは、`stale`を返し、画面に「行番号がずれているかもしれない」と出す。
- 回答の`ref`は、依頼票に出ているファイルの`ファイル名#L行`も受け付ける。ファイルの長さは見ず、行は1以上、開始≦終了、100,000以下だけ確かめる。

## 理由

- 「無関係」を解析で言い切る必要はない。3段目は閲覧の補助で、依頼票の構造（対象、順序、データの流れ）には加えない（ADR-0002）。
- 依頼票に出ていないファイルは読まないので、画面からリポジトリ内の任意のファイルを読む経路にはならない。

## 影響

- 必須の再依頼の`prior`は、ファイル名の参照を指摘のシンボルに数えない（シンボルを指さない指摘ではなく、ファイルの行の指摘）。ファイルの行を指摘した場合、`prior`で畳むシンボルは減らない。
- 3段目で見る行は、依頼票のコードではなく作業ツリーのもの。

## 却下した代替案

- 依頼票にファイル全体を入れる: 記録が大きくなる。
- 変更行の前後だけの中間表示を足す: 今の表示（シンボル全体）を保つ。必要なら別のADRで決める。

## 検証

`npm test`で、`inloop_get_file`が依頼票に出たファイルだけ返すこと、ファイル名の参照を受け付け、範囲外を拒否することを確かめた。実ブラウザのe2eで、開く・行クリックの位置・閉じるを確かめた。実際のクライアントでの表示は未検証。
