# ADR-0031: SQLの列を取り出し、`tables`と`table`の当て方に足す

- 状態: Accepted
- 日付: 2026-10-12
- Supersedes: なし（ADR-0026の「列は扱わない」、ADR-0028の「列での当て方は後で決める」を、ここで足す）

## 背景

`tables`は「`users`を書く」までしか示さず、`users.role`を変える変更と`users.name`を変える変更が同じに見えた。信頼境界は列の単位で引かれることが多い（権限、状態、金額）。

## 決定

- 依頼票の`tables`の項目に、省略できる`columns`（列名の配列）を足す。記録の版は1のまま。
  - 書く列: `INSERT INTO t(a, b)`は`a`・`b`、`UPDATE t SET a = ...`は`a`、`ON CONFLICT ... DO UPDATE SET`は挿入先の列に足す。列の並びがない`INSERT`、`DELETE`、左辺が`(a, b)`の形は`*`。
  - 読む列: `別名.列`・`テーブル名.列`は、別名の対応で結び付ける。`x.*`と`SELECT *`は`*`。別名のない列は、文に読むテーブルが1つだけ（CTEとUPDATEがない）ならそのテーブルの列、そうでなければ決められないので、読むテーブルすべてに`*`を付ける。
  - `*`は「全列、または列を決められない」。列が1つも読み取れない読み（`count(*)`だけなど）とスキーマの変更には`columns`を付けない。
  - 文は`;`で分けて読む。集めた列は、同じ（シンボル, テーブル, 種類, 経由）で合わせる。`*`を先頭、ほかは名前順。
- 信頼境界ルールの`table`の当て方に、省略できる`columns`（globの配列、大文字小文字を区別しない）を足す。指定すると、その列に触れるSQLだけに当たる。`*`を持つSQLと、スキーマの変更（列を読み取れない）には当てる。
- 画面の「データベースのテーブル」に`（列, ...）`を出す。`*`は「全列または不明」と出す。

## 理由

- テーブルより細かい単位でルールを書けるのに、列を決められないときは当たる側に倒すので、見落としの経路を作らない（ADR-0001、AGENTS.md）。
- 結び付けられない列を推測で割り当てず、`*`で「決められない」と示す（ADR-0002）。

## 影響

- 古い実装は`columns`のある`inloop.json`を拒否する（ADR-0022）。`minVersion`で防げる。依頼票の`columns`は、知らない項目として無視される。
- 字句による簡易的な読みなので、次は読み違える。暗黙の別名（`SELECT a b`の`b`）と`ORDER BY`の別名は列として数えうる（多く出る側）。`UPDATE`・`DELETE`の`WHERE`の列は出さない。副問い合わせの中は、文全体の読むテーブルとして扱う。`INSERT ... SELECT`の列は、読む側の表の列として扱う。
- スキーマの列（`CREATE TABLE`の定義）は読まない。

## 却下した代替案

- SQLパーサーの依存を足す: ADR-0026と同じ理由。
- 結び付けられない列を捨てる: 列で絞ったルールが当たらなくなる穴になる。

## 検証

`npm test`で、書く列・読む列・別名・`*`・複数の文・列の合算・`columns`の当たり方（`*`とスキーマに当たること）・形の拒否を確かめる。画面の表示（Playwright）と実際のクライアントでの表示は未検証。
