# ADR-0018: 画面からコメント欄と送信ボタンを外し、承認・保留を押したらすぐ記録する

- 状態: Accepted
- 日付: 2026-10-11
- Supersedes: ADR-0016の一部（AIが`inloop wait`を既定で動かすこと）

## 背景

ADR-0017で議論を会話に移した。利用者から、会話が中心なら`inloop wait`は要らない（待ち受けの終了でAIが起こされ、返事が遅くなる）、「まとめて送信」も要らない（まとめて承認ならわかる）、コメント欄も外す、と決めた（2026-10-11）。

## 決定

- 画面からコメント欄（修正依頼・質問の入力）と「まとめて送信」を外す。修正依頼と質問は会話で行う。
- 各依頼の「承認」「保留」は、押したらすぐ記録する。未回答の依頼が2件以上なら「まとめて承認」を出す。MCP Appsの埋め込みでは、記録した回答を会話に送る。
- 行のクリックは、いつでも位置のコピーにする（Shiftで範囲）。
- AIは依頼のURLを開いたら手番を終えて会話を待つ。`inloop wait`は既定では動かさない（コマンドは、画面だけで答えたい人のために残す）。ツールの説明文と雛形の指示を直した。

## 影響

- サーバーの`inloop_submit`は、修正依頼・質問も受け付けたままにする（記録の形は変えない）。
- 画面だけで修正依頼を出す手段はなくなる。

## 検証

`INLOOP_UI_E2E=1 npm test`で、コメント欄と送信ボタンがないこと、承認・保留・まとめて承認がすぐ記録され会話に届くこと、行のクリックで位置をコピーすることを確かめる。
